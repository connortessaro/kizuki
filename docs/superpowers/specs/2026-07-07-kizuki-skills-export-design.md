# Kizuki — skills export (installable ritual pack)

**Date:** 2026-07-07
**Status:** design approved, pre-implementation
**Backlog origin:** `docs/BACKLOG.md` — "Distribute rituals as an open Agent Skills
pack (`npx skills add tessaro/kizuki`) — partial: `scripts/install-codex-prompts.mjs`
for Codex; broader pack TBD."

## Goal

Distribute Kizuki's rituals as installable skills for multiple agents from one
neutral source. `kizuki skills export` renders per-agent files and installs them;
rendered output is also committed so pure-markdown users (or a community
`npx skills` installer) get the files without installing the CLI first.

Chosen over MCP-prompt / probe-pack approaches (see the ADHD ideation in this
session): lowest risk, ships today, and makes the pack a build artifact of the
binary so instructions cannot drift from the code. MCP-served rituals stay a
possible follow-up.

## Coupling note

A rendered skill is instructions only; it cannot run the pipeline alone. Rendered
rituals invoke the installed `kizuki` binary on PATH (not `./kizuki`). Making the
rituals work over MCP with no CLI would require new MCP action tools
(`start_shift` etc.) that do not exist — explicitly out of scope here.

## Components

### Neutral source — `skills/<name>/ritual.md` (new)

One directory per ritual. Two rituals to start (everything that exists today):
`kizuki-start`, `kizuki-stop`. Each file:

```markdown
---
name: kizuki-start
description: <one-line, used as skill/prompt description>
invoke: kizuki start
---

<body: the ritual instructions, referencing the global `kizuki` binary>
```

Body is ported from the current `codex/prompts/*.md`, with `./kizuki` changed to
`kizuki` (global bin, not in-repo). Frontmatter keys: `name`, `description`,
`invoke`.

### `lib/skills.mjs` (new, zero-dep, pure)

- `parseRitual(source)` → `{ name, description, invoke, body }`. Validates the
  three frontmatter keys are present; throws loudly if missing (no silent
  defaults). `name` is path-safe (reuse the `assertName` rule — no `/`, `\`, `..`).
- `readRituals(skillsDir)` → array of parsed rituals (reads `skills/*/ritual.md`).
- `renderClaude(ritual)` → SKILL.md string: frontmatter (`name`, `description`) +
  blank line + body.
- `renderCodex(ritual)` → plain body string (Codex prompt format, no frontmatter).
- `TARGETS = { claude, codex }` mapping target → `{ render, distPath(name),
  homePath(name, home) }` so the CLI and tests share one definition.

### CLI — `kizuki skills export [--agent claude|codex|all] [--check]`

Dispatched in the `kizuki` executable (new `skills` subcommand with an `export`
action).

- Default (`--agent all`, no `--check`): render each ritual for each target and
  write into the user's agent dirs:
  - claude → `~/.claude/skills/<name>/SKILL.md`
  - codex → `~/.codex/prompts/<name>.md`
  Print each written path.
- `--agent claude|codex`: only that target.
- `--dist`: render into the committed `dist/skills/` tree instead of the home
  dirs (the build step that produces committed output).
- `--check`: render from source and compare against the committed `dist/` files;
  exit non-zero and name the drifted file if any differ; write nothing. (CI guard
  so committed output never goes stale — run `--dist` to fix drift.)

### Committed output — `dist/skills/`

Rendered files committed to the repo:

- `dist/skills/claude/<name>/SKILL.md`
- `dist/skills/codex/<name>.md`

Generated by `kizuki skills export --dist`. Pure-markdown / `npx skills` users
copy these directly. `--check` diffs source-render against these.

### Replace `scripts/install-codex-prompts.mjs`

Its behavior (copy prompts into `~/.codex/prompts/`) is subsumed by
`kizuki skills export --agent codex`. Delete the script; update any README/AGENTS
reference to point at the new command.

### README

Add an install section: `npm i -g kizuki && kizuki skills export`, plus the
pure-markdown path (grab `dist/skills/...`). Note rituals need the `kizuki` binary

## Error handling

- Missing/invalid frontmatter key in a ritual source → throw, name the file.
- Unsafe ritual `name` → throw (path-safety, same rule as entities).
- `--check` drift → non-zero exit, name the first drifted file. No silent pass.

## Testing — `lib/skills.test.mjs`

- `parseRitual` extracts the three keys + body; throws on a missing key.
- `parseRitual` rejects an unsafe `name`.
- `renderClaude` output starts with frontmatter containing `name`/`description`
  then the body.
- `renderCodex` output is the plain body (no frontmatter).
- Rendered bodies invoke `kizuki` (not `./kizuki`).
- export installs to a tmp home: claude SKILL.md and codex prompt land at the
  expected paths.
- `--check` passes when `dist/` matches source and fails (named file) on drift.

All filesystem tests use tmp dirs; no writes to the real home.

## Non-goals

- No MCP-served rituals, no probe/self-selecting pack, no new MCP action tools.
- No new rituals beyond the two that exist.
- No npm publish automation (README documents the manual path).
- No new runtime dependencies. ESM `.mjs`, Node built-ins, `node:test`.
